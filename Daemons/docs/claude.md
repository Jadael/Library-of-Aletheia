# Daemons/docs - Implementation Documentation

## Overview

The `Daemons/docs/` folder contains detailed implementation documentation for the daemon systems. These are LLM-generated markdown files that provide in-depth explanations of each daemon's functionality, architecture, and usage.

**Location in Project:** `/Daemons/docs/`
**Related Documentation:**
- [../../claude.md](../../claude.md) - Root project documentation
- [../claude.md](../claude.md) - Parent Daemons folder documentation
- [../Scenes/claude.md](../Scenes/claude.md) - UI scenes documentation

## Purpose

This folder serves as:
- **Implementation Reference** - Detailed documentation of daemon internals
- **LLM-Generated Docs** - Created by Aletheia's self-documentation system
- **Developer Guide** - Understanding how each daemon works
- **Historical Record** - Snapshots of daemon functionality (see `last_updated` in frontmatter)

## Documentation Format

Each file follows this structure (from YAML frontmatter):

```markdown
---
title: [DaemonName]
last_updated: [ISO 8601 timestamp]
---

# [DaemonName]

## Properties
- Exported variables and their purposes
- Configuration options

## Signals
- Signal definitions
- When they're emitted
- What they communicate

## Functions
### [function_name]
`func signature`

﴾Detailed explanation in mystical/metaphorical language describing:
- Purpose and context
- Expected inputs
- Output and behavior
- Implementation details and intricacies
﴿
```

## Generating Documentation

Documentation is generated by the Aletheia daemon:

```gdscript
# Trigger documentation generation
Aletheia.generate_project_documentation()

# Or call from command/console
Aletheia.generate_documentation()
```

This process:
1. Scans GDScript files in configured folder
2. Analyzes code structure with CodeSeer
3. Generates documentation with LLM assistance
4. Saves markdown files to this folder
5. Includes YAML frontmatter with metadata

## Usage Patterns

### For Developers
- Read these files to understand daemon implementation
- Reference when modifying daemon behavior
- Check `last_updated` to determine if regeneration is needed

### For LLMs/AI Assistants
- Provides high-level understanding of daemon purpose
- Explains design decisions and architecture
- Helps with code comprehension and modification

### For Documentation Maintenance
- Regenerate when significant changes occur
- Update `last_updated` metadata
- Ensure consistency with source code

## Common Tasks

**Reading Documentation:**
```bash
# Read specific daemon docs
cat Daemons/docs/Aletheia.md

# Search for specific functionality
grep -r "signal" Daemons/docs/*.md
```

**Regenerating Documentation:**
```gdscript
# In Godot console or script
Aletheia.generate_project_documentation()
```

**Finding Outdated Docs:**
```bash
# Compare timestamps in frontmatter with git log
ls -lt Daemons/docs/*.md
```
